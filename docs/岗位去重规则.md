# 岗位去重规则（第一遍筛）

## 1. 目标

同一家公司在不同平台/不同批次发布的同一岗位，只保留一条，保留最新可确认的那条；避免重复岗位进入 AI 分类、URL 校验和日报。

## 2. 分组键

```
company_id + 归一化标题 + 归一化城市
```

- 标题：NFKC、转小写、去括号内容、去空格/标点。
- 城市：取第一段（`北京/上海` → `北京`），去掉“市”。
- 例：`AI 全栈工程师` 与 `AI全栈工程师` 同组。

## 3. 合并条件

同一组内，满足任一条件才合并：

1. `apply URL` 完全相同；
2. 岗位描述相似度 `>= 0.62`（中文二元组 + 英文词 Jaccard）。

**不合并**：同标题同城市但描述差异大（可能是不同团队/不同岗位）。

## 4. 保留规则

- 先按 `last_seen` 降序；
- 再按来源优先级：ATS/官网 > 聚合器 > 招聘平台；
- 保留最新、来源更硬的一条；
- 其他条目标 `status='merged'`，写 `duplicate_of`、`merged_at`，不物理删除，保留审计；
- 证据 URL 合并到保留岗位的 `job_evidence`。

## 5. 执行顺序

```
采集 → 去重（本脚本） → AI 分类 → URL 核验 → 前端/日报
```

当前采集器在入库时先写 `ai_relevance`；去重后会按保留岗位重新核验，不依赖旧分类。

## 6. 命令

```powershell
python tools\dedup_jobs.py
python tools\verify_jobs.py --limit 1000 --workers 24
```
